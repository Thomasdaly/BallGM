Clear the ground Milestone 6 stands on: make `LeagueRuleset` describe leagues it currently cannot, and add the four things `docs/negotiation-mechanisms.md` says Milestone 6 cannot defer — in one `schemaVersion` 4 bump rather than two breaking changes six weeks apart.

This is a prerequisite task, not a milestone. Nothing here is a feature a player sees. It exists because `prompts/09-negotiation-and-free-agency.md` assumes machinery that is not there: a payroll floor that does not exist, a cap charge that cannot represent a hold, and a `Player` with no age or service time to key a tier table off. Doing it first is cheaper than discovering it three commits into the negotiation aggregate.

Editing them is the point — do not treat a red conformance test as a regression.

**Get explicit sign-off before writing code.** This is simultaneously a save/mod schema compatibility change and a change to public APIs consumed across projects, both of which `CLAUDE.md` puts under change control. Propose first; do not move the version constant on your own initiative.

Scope, in dependency order:

- **Optional-by-absence cap system.** `CapThresholds`' five properties become `Money?`. The non-decreasing ordering check applies only to thresholds that are present, in the same fixed sequence. Add `CapThresholds.Uncapped`. `CapLedger` builds a standing only for a configured threshold, so an uncapped league yields a cap sheet carrying a real payroll and an empty standings list — which is the truth, rather than five zeroes every team is over. `TeamCapSheet.StandingFor` returns `ThresholdStanding?` instead of throwing out of a `.Single(...)`.
- **Payroll floor.** A new first link *below* the soft cap — the current chain assumes non-decreasing from `SoftCap` up, so this extends the chain rather than inserting into it. Reporting only: a team under the floor produces a stated, explainable standing. The penalty is Milestone 10 and stays there.
- **No-draft leagues.** `DraftRules` accepts `roundCount: 0` as "this league has no draft", exposes `HasDraft`, and drops the retained-round requirement in that case. A franchise in such a league cannot be handed picks a draft will never hold.
- **Absence versus zero.** An omitted `salaryMatchPercent` currently deserializes as `0`, and `TradeRules.Create` correctly rejects `0` as a typo — so "this rule does not apply" and "someone fat-fingered a field" are the same input today. Resolve it, and state in a comment which reading you chose and why. No new JSON keys: absence carries the meaning, per the existing proposal.
- **`TradeValidator.CheckMoney` skips explicitly, never accidentally.** No soft cap, no salary matching. No hard cap, no ceiling check. No apron, no apron restriction. Each an early return with a comment naming the rule it is skipping and a rule code in the assessment saying so — a check that silently passes because a value was null is indistinguishable from a check that ran, and that is the class of bug this whole task exists to kill.
- **`CapCharge` can express a hold.** A roster-slot hold is a charge for a player who does not exist yet: it has neither `PlayerId` nor `ContractId`, both currently required and non-nullable. Decide now, before `CapLedger.Evaluate` is edited twice — either those two become optional for the hold kind, or holds become a sibling type `TeamCapSheet` sums alongside charges. State the trade-off; the second is more types and fewer nulls.
- **`Player` gains age and service time.** The one Milestone 6 prerequisite with no workaround: every tier table in `docs/negotiation-mechanisms.md` keys off seasons of service, and preference (money versus term, contender versus role) is largely an age story. Keep it minimal and temporal — birth date or age, seasons of service, and nothing else. Career history proper is Milestone 8, and biography fields for the relationship graph are Milestone 13; do not start either here.
- **`Contract` gains a clause seam.** Not clauses themselves — a shape that does not assume compensation and term are the whole of a deal, so movement-consent and buyouts (both Milestone 9) do not force a second breaking contract change. The smallest thing that keeps the door open; if that is nothing but a documented decision, say so rather than adding a speculative empty collection.

Constraints:

- Fictional and generic throughout. No real-league branding, no real agreement's term for anything, and no rule that only one league could ever use. `docs/negotiation-mechanisms.md` → "Naming rule" governs every field name added here.
- A v3 reader handed a v4 file must fail structurally and explainably, not default missing fields to zero and run — that silent-zero path is gap 1 and it is live in `main` right now. Version the envelope, check it on load, and return a `DomainOperationResult` failure, never an exception.
- Ship a migration path for existing v3 ruleset files, or state plainly that none exists and why that is acceptable at this stage. Do not leave it implied.
- Runtime types stay separate from serialized shapes. `LeagueRulesetEnvelope`/`LeagueRulesetSerializer` absorb the schema change; `LeagueRuleset` itself should not grow a nullable field because JSON has one.
- Boundaries unchanged. `ArchitectureBoundaryTests` still governs, `BallGM.Domain` still has zero project references, and the cap-sheet view model gets nullable-aware rendering rather than rules logic.
- No suppressed nullable warnings. The whole task is about making absence explicit; suppressing a warning to move faster inverts it.
